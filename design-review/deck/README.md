# 卡盒图鉴重设计验收

## 最终行为

- 进入图鉴：封闭的三维收藏卡盒，可选择随机抽一张、手动抽卡或全部抽出。默认保留卡片信息区的间距，抽取前后按钮不跳动。
- 手动抽卡：卡盒停在左侧，卡背扇形展开；悬停只向上推选中的卡背，保持原有叠放层级，不自动翻面。点击或触屏点按后在该牌位置翻面，不移到中央；保持展示和详情入口，点击其他牌切换，点击舞台空白或按 Esc 翻回。保留方向键选牌与回车翻面，不显示额外的左右按钮或选牌提示。
- 单抽：开盖、从盒口升起卡背、悬停、翻面展示完整卡面。
- 再抽：旧卡归入牌堆，盒盖保持打开，继续抽下一张；避免立即抽到同一张。
- 全抽：整叠升起、扇开、连续移动到原图鉴网格。
- 收回：网格聚拢、翻回卡背、整叠入盒并合盖；单卡也有入盒合盖动作。

## 截图循环与检查

已根据实际浏览器截图调整主体大小、镜头余量、移动端文字遮挡、卡盒与卡牌比例、落位时的图片比例和交叉淡化。后续按用户反馈补充收回动画，以及连续抽卡保持开盖。

桌面在 1280×720、1440×900 下检查；手机按 390×844 的真实布局视口检查，并通过临时 iframe 完成最后一轮交互验收。临时页面已移除。

- 展开后为 20 个卡牌链接；没有横向溢出或残留动画层。
- 完整收回后恢复盒态，随机抽取按钮可用。
- 连续抽取时盒盖保持打开，新卡标题、编号和详情链接一致。
- 本次手动抽卡实测：悬停 900 毫秒仍只有抬起的卡背；点击后左侧与右侧的牌均在各自位置翻面，切换后只有新牌正面。Esc 退出后信息隐藏。全部抽出后有 20 张卡牌、无残留动画层。
- 手机尺寸下扇牌和最右侧卡片预览完整显示，选中第 20 张后标题与卡面一致。
- 桌面与手机交互检查未捕获到 JavaScript 错误或警告。
- `node --check`、生产构建和 `git diff --check` 通过。

关键帧能判断构图、遮挡、比例与状态衔接，不能证明连续播放的帧率或主观流畅程度；手感需以实际预览为准。

## 扇牌到平铺的性能优化

落位动画复用 Three.js 已解码的 600×900 卡面画布，并提前逐张解码图鉴图片。目的地一次性读取，图层批量加入；动画使用固定尺寸的图层，通过 transform、clip-path 和 opacity 完成位移、等比缩放与裁切，避免逐帧修改 left、top、width、height。裁切完成后再与网格交替淡入。20 张卡牌均参与移动，包括落向屏幕外的卡牌。

同一本机浏览器、1200×900 iframe 中，requestAnimationFrame 采样结果如下（单次对照，不代表所有设备的帧率）：

| 平铺阶段 | 优化前 | 优化后 |
| --- | ---: | ---: |
| P95 帧间隔 | 33.7 ms | 17.6 ms |
| 最长帧间隔 | 50.6 ms | 17.6 ms |
| 超过 32 ms 的帧 | 5 | 0 |

原始采样：[优化前](performance-before.json)、[优化后](performance-after.json)。临时测量页面已移除。
